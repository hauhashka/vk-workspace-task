# Тестовое задание: платформа ИИ-агентов в VK WorkSpace

Отбор в проект «Развитие платформы для ИИ-агентов в корпоративном
мессенджере VK WorkSpace», VK Tech. Репозиторий содержит все три части задания.

```
msgfmt/      часть 1: C++17-библиотека и CLI разбора разметки → текст + диапазоны UTF-16
service/     часть 2: служба ghreport на Go (сводка по открытым issue GitHub) + Dockerfile
api_tests/   часть 3: интеграционные тесты ghreport на pytest + совместимый сервер-заглушка
```

## Быстрый запуск

```sh
# Часть 1
cmake -S msgfmt -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build
printf 'Привет, **мир**!' | ./build/msgfmt

# Часть 2
(cd service && gofmt -l . && go vet ./... && go test ./...)
docker build -t ghreport service/
docker run --rm -e GITHUB_TOKEN=... ghreport --repos cli/cli --limit 20 --out -

# Часть 3 (сама соберёт службу и поднимет заглушку API)
python -m pip install -r api_tests/requirements.txt
pytest api_tests -q
```

Подробности по каждой части есть в `msgfmt/README.md`, `service/README.md` и
`api_tests/README.md`.

| Проверка | Результат |

| `gofmt -l .`, `go vet ./...`, `go test -race ./...` | чисто, все тесты проходят |
| `pytest api_tests -q` против `stub_server.py` | 26 passed, ~3 с |
| мутационная проверка набора (5 поломок сервера, 11 поломок службы) | каждая поломка обнаружена |

Не проверено в моём окружении: `docker build` (не было Docker-демона) и запуск
против настоящего `api.github.com` (не было доступа к сети). Dockerfile
написан по стандартной схеме multi-stage + distroless nonroot.

## Ключевые решения

* **msgfmt.** Строгая проверка UTF-8 выполняется до разбора. Разбор идёт
  однопроходно по кодовым точкам, и закрывающий маркер ищется только внутри
  родительской конструкции, поэтому частичные пересечения диапазонов
  невозможны по построению. Экранированные символы не могут закрыть стиль.
  Корректность проверяется таблицей примеров и свойствами на 20 000 случайных
  входов: границы диапазонов, сортировка, вложенность, `parse(escape(x)) == x`.
* **ghreport.** Код разделён на слои: аргументы → обход страниц → HTTP-клиент
  → кэш/журнал. Перенаправления обрабатываются вручную, чтобы каждая попытка
  попадала в журнал, а токен не уходил на чужой хост. Кэш хранит ещё и `Link`,
  чтобы обход продолжался по ответу 304. Ожидание лимита ограничено 15 минутами
  и 5 повторами. Коды возврата: 0, 1 (частичный отчёт), 2 (аргументы),
  3 (`unauthorized` или `all_failed`).
* **api_tests.** Ожидаемый результат не зашит в тесты: эталон строится прямым
  обходом того же API. Поэтому набор работает с любым совместимым сервером, а
  для локального прогона есть заглушка с переключаемыми нарушениями контракта.

## Допущения

Таблицы задания (приложение А, аргументы, переменные окружения, коды возврата,
соответствие полей) учтены полностью. Что осталось на моё усмотрение:

* имена репозиториев тестового сервера заранее неизвестны, поэтому они задаются
  переменными `GHREPORT_TEST_*`; по умолчанию используются имена заглушки
  (`stub/alpha`, `stub/missing`, `stub/ratelimited`);
* 401 проверяется запуском с заведомо неверным токеном `invalid-…`;
* ожидание лимита ограничено 5 повторами и 15 минутами на одну паузу.
