# msgfmt

Библиотека и утилита командной строки на C++17, которые превращают сообщение
в подмножестве Markdown в пару «чистый текст + список стилевых диапазонов».
Позиции диапазонов считаются в кодовых единицах UTF-16, как в format ranges
Bot API корпоративных мессенджеров. Зависимостей, кроме стандартной библиотеки, нет.

## Сборка и тесты

```sh
cmake -S msgfmt -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build
```

Опции CMake:

| Опция | По умолчанию | Назначение |
|---|---|---|
| `MSGFMT_SANITIZE` | `OFF` | сборка с `-fsanitize=address,undefined` |
| `MSGFMT_WERROR` | `OFF` | предупреждения считаются ошибками |

Флаги `-Wall -Wextra` включены всегда. Проверка с санитайзерами:

```sh
cmake -S msgfmt -B build-asan -DCMAKE_BUILD_TYPE=Debug -DMSGFMT_SANITIZE=ON -DMSGFMT_WERROR=ON
cmake --build build-asan && ctest --test-dir build-asan --output-on-failure
```

В CTest зарегистрированы два теста:

* `unit` (`tests/test_msgfmt.cpp`) - все 15 контрольных примеров приложения А, таблица контрольных примеров по всем правилам
  разбора, некорректный UTF-8, экранирование, JSON и 20 000 случайных входов
  с фиксированным зерном. На случайных входах проверяются свойства: диапазоны
  не выходят за текст, отсортированы, не пересекаются частично, а
  `parse(escape(x))` возвращает `x` без диапазонов;
* `cli` (`tests/run_cli.cmake`) - запуск бинарника на файлах из `tests/cli_cases/`
  с побайтовым сравнением stdout и проверкой кода возврата.

## Использование

```sh
$ printf 'Привет, **мир**!' | ./build/msgfmt
{"text": "Привет, мир!", "ranges": [{"style": "bold", "offset": 8, "length": 3, "url": ""}]}

$ printf '**жирный _и_ курсив** [ссылка](https://vk.com) 😀 `x`' | ./build/msgfmt
{"text": "жирный и курсив ссылка 😀 x", "ranges": [{"style": "bold", "offset": 0, "length": 15, "url": ""}, {"style": "italic", "offset": 7, "length": 1, "url": ""}, {"style": "link", "offset": 16, "length": 6, "url": "https://vk.com"}, {"style": "code", "offset": 26, "length": 1, "url": ""}]}

$ printf '2 * 3' | ./build/msgfmt escape
2 \* 3

$ printf '\377' | ./build/msgfmt; echo $?
{"error": "invalid_utf8"}
2
```

Коды возврата: `0` - успех, `2` - некорректный UTF-8, `1` - неизвестные аргументы
командной строки (этот случай заданием не описан).

API (`include/msgfmt/msgfmt.hpp`):

```cpp
msgfmt::Message m = msgfmt::parse(input);   // бросает msgfmt::InvalidUtf8
std::string safe  = msgfmt::escape(text);    // бросает msgfmt::InvalidUtf8
std::string json  = msgfmt::to_json(m);
```

## Принятые решения

* **Сначала проверка, потом разбор.** Вход целиком декодируется строгим
  декодером UTF-8: overlong-формы, суррогаты (U+D800..U+DFFF), коды выше
  U+10FFFF и обрезанные последовательности считаются ошибкой. Затем разбор
  идёт по массиву кодовых точек, а смещения считаются в UTF-16 при выводе
  символов.
* **Закрывающий маркер ищется только внутри текущего сегмента.** Каждая
  конструкция ищет ближайший закрывающий маркер в пределах родительской
  конструкции, а потом рекурсивно разбирает своё содержимое с пометкой
  «этот стиль уже открыт». Поэтому частичные пересечения диапазонов
  невозможны по построению. Глубина рекурсии не больше четырёх, по числу стилей.
* **Экранированные символы не могут быть маркерами.** При поиске закрывающего
  маркера пары `\` + служебный символ пропускаются, так же как при выводе
  текста. Поэтому `**a\**` не закрывается и выводится как `**a**`.
* **Содержимое должно быть непустым.** Правила 3 и 4 требуют непробельный
  символ после открывающего маркера, а правило 5 требует непробельный символ
  перед закрывающим. Из этого следует, что `****`, ``` `` ``` и `[](u)` остаются
  литералами.
* **`**`, не ставший маркером, выводится целиком.** Оба символа уходят в текст,
  и второй `*` не пробует открыть конструкцию заново.
* **Граница слова для `_`** проверяется по соседним символам исходной строки.
  Закрывающий `_` смотрит на следующий символ всего входа, а не сегмента: на
  границе сегмента всегда стоит служебный маркер, который не является буквой.
* **Ссылка.** Текст ссылки ограничен ближайшей неэкранированной `]`, разбирается
  рекурсивно и может содержать другие стили. URL берётся как есть до ближайшей
  `)`, экранирование в нём не применяется. Пробельный символ в URL или пустой
  URL делают всю конструкцию литералами.
* **Порядок диапазонов**: `offset` по возрастанию, затем `length` по убыванию,
  затем порядок открывающих маркеров во входе (`stable_sort` по номеру открытия).
* **JSON.** Пишется вручную: `"`, `\` и управляющие символы (включая `\u0000`
  и DEL) экранируются, остальной UTF-8 выводится как есть. После объекта идёт
  перевод строки. Вывод `escape` повторяет байты без добавленного перевода строки.

## Известные ограничения

* «Буква или цифра» для правила о `_` определяется по встроенной таблице
  диапазонов: латиница, кириллица, греческий, армянский, грузинский, иврит,
  арабский, тайский, кана, CJK, хангыль, ASCII-цифры. Полной таблицы
  категорий Unicode нет, поэтому буквы редких письменностей считаются
  «не буквами». «Пробельный символ» - это ASCII-пробелы и пробелы Unicode из
  категории Zs, плюс U+0085, U+2028, U+2029.
* Поиск закрывающего маркера линейный, поэтому на патологических входах
  (тысячи незакрытых `_` или `**`) время разбора квадратично от длины.
  Для сообщений мессенджера это не важно.
* Нормализация Unicode не выполняется намеренно, этого требует задание.
